# 多工具同时使用优化方案

## 一、现状诊断

| 项 | 现状 | 后果 |
|---|---|---|
| 引擎生命周期 | 全部工具的运行引擎（Timer / 录音器 / 音频流 / 状态机）**活在页面 State 内** | 切换工具 = 页面销毁 = 引擎销毁 |
| 内容区 | 单 pane 单页显示，`AnimatedSwitcher` 替换 | 同一时刻只能看到一个工具 |
| 移动端 | `Navigator.push` 全屏页，返回即关 | 同上 |

**根因**：工具 = 页面。页面没了，工具就没了。

## 二、目标场景

1. **持续运行**：录音 / 分贝 / 耳返 / 秒表 / 倒计时 / 番茄钟——切走查看别的工具时，**运行不能断，状态要可见可回**
2. **组合使用**：一边听小说朗读、一边看倒计时；一边录音、一边记笔记
3. **桌面端专业感**：运行中的工具能"小窗化"，不占主区

## 三、方案：四层（按价值排序，可分期实施）

### P0 · 工具会话常驻（核心，解决根因）

**思路**：把"工具 = 页面"拆成「**引擎（Session）**」与「**视图（View）**」。

- 新建 `ToolSessionRegistry`（全局单例）：
  - 每个持续型工具在首次打开时创建 **Session**（持有 Timer / 录音器 / 音频流 / 状态）
  - 页面只是 Session 的**视图**，重建时重新绑定，数据不丢
  - 页面销毁**不销毁 Session**，只解绑视图
- 改造范围（6 个持续型工具）：
  `recorder`（录音器提升为 Session）· `decibel` · `ear_monitor` · `stopwatch` · `countdown` · `pomodoro`
- 交互效果：
  - 录音中切到文本工具 → 录音继续，回来界面恢复
  - 倒计时跑着去用别处 → 时间继续走，回来还在

### P1 · 全局运行状态条（常驻可回）

- 内容区顶部增加**运行状态胶囊条**（仅当有 Session 在运行）：
  `● 录音中 02:13   ⏱ 倒计时 04:30   [停止]`
- 每条胶囊：点击跳回对应工具、带停止按钮、多会话并排
- 效果：任何工具页都能看到"谁在跑"，一键回跳/停止

### P2 · 桌面端悬浮小窗（专业感）

- 运行中的会话可点「小窗化」→ 内容区上方浮现**可拖动迷你面板**（约 240×120：状态 + 播放/暂停/停止）
- 主区继续使用其他工具，小窗始终置顶（Flutter `Overlay` + `Draggable`，无需系统窗口）
- 适合：录音电平、倒计时、番茄钟

### P3 · 多开 Tab（通用组合）

- 内容区改为 **Tab 栏多开**：同时打开「阅读 + 倒计时」等多个工具页，Tab 切换
- 侧栏骨架不变；适合任意工具组合、多实例（如两个倒计时）

## 四、实施代价与顺序

| 阶段 | 改动 | 风险 | 建议 |
|---|---|---|---|
| P0 会话常驻 | 6 工具引擎外提 + 注册表 | 中（需逐个工具重绑视图） | **先做，一次性到位** |
| P1 状态条 | 注册表 + 顶部胶囊组件 | 低 | 与 P0 同轮完成 |
| P2 悬浮小窗 | Overlay 面板 + 拖拽 | 中 | 桌面端二期 |
| P3 Tab 多开 | 内容区 Tab 容器 | 中 | 三期可选 |

## 五、备选对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 会话常驻 + 状态条（推荐） | 直接解决"切走就断"，改动可控 | 无同屏并排 | ✅ P0/P1 采纳 |
| 分屏两栏 | 真并排 | 只支持两两组合、组合切换复杂、移动端不适用 | 不采纳 |
| 系统多窗口 | 真独立 | Flutter 多窗口需多 entrypoint，重构大 | 不采纳 |
| 系统级悬浮窗（移动端） | 全局可见 | 需悬浮窗权限，iOS 不支持 | 不采纳 |

## 六、验收标准

- 录音 / 计时类工具切页后：**运行不断、回页状态恢复**（可对照当前版本验证：当前切页即断）
- 运行状态条正确显示所有运行中会话，点击回跳、可停止
- 桌面端构建通过、启动正常
