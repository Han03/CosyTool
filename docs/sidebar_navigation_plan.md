# 桌面端侧栏导航优化方案

## 一、现状诊断

当前桌面侧栏为「全量平铺列表」：19 个条目（首页 + 17 款工具 + 设置/关于）自上而下线性排列。

| 问题 | 根因 |
|---|---|
| 工具多了滚动条变长 | 侧栏承载了**所有工具的全量列表**，任何窗口高度下都需要滚动才能到达底部工具 |
| 与首页内容重复 | 首页本已是「分组 + 搜索 + 卡片」的完整工具总览，侧栏又平铺了一遍全部工具，信息双重冗余 |

## 二、设计原则：三层导航分工

侧栏应回归"**全局骨架导航**"的定位，而不是内容列表：

| 层 | 载体 | 职责 |
|---|---|---|
| 全局导航（骨架） | 侧栏 | 结构性入口：首页 / 分组 / 设置 / 关于，秒达、不滚动 |
| 完整总览 | 首页 | 分组卡片 + 搜索 + 描述，探索与发现 |
| 长尾直达 | Ctrl+K 命令面板 | 任意工具一步跳转，无需翻找 |

侧栏只保留"骨架"，全量列表交给首页与命令面板——这是 VS Code、飞书桌面端等专业产品的通行做法。

## 三、具体方案：分组折叠导航

### 3.1 结构

侧栏从「19 项平铺」改为「4 组折叠 + 4 固定入口」：

```
[首页]                     ← 固定
▸ 音频 (3)                ← 折叠组，展开后显示 3 款工具
▸ 计时 (4)
▸ 文本 (3)
▸ 日常工具 (5)
───────
[设置]                     ← 固定
[关于]                     ← 固定
```

默认全部收起时仅 7 项，**任何窗口高度都不再需要滚动**；展开一组最多 5 项，滚动需求基本消除。

### 3.2 分组与首页同源

- 分组划分直接复用首页的 `_ToolGroup` 白名单（音频 / 计时 / 文本 / 日常），保证侧栏与首页信息架构一致
- 组标题显示工具数量，展开后子项缩进，与首页网格呼应

### 3.3 交互细节

1. **折叠动画**：组标题箭头 120ms 旋转过渡，展开/收起组内容用 `AnimatedSize`（200ms）
2. **选中联动**：
   - 从首页或命令面板打开某工具 → 侧栏自动展开其所在分组并高亮该项
   - 分组高亮项沿用现有 3px 品牌绿指示条
3. **状态记忆**：用户手动展开/收起的分组持久化到 shared_preferences，重启后保持
4. **固定入口**：设置、关于始终固定在底部（分隔线上方），不随分组滚动

### 3.4 视觉

- 组标题：`labelLarge` + 600 字重 + 组图标（沿用首页同款图标），hover 背景微亮
- 子项：保持现有 `ListTile` + 品牌绿指示条样式，左侧缩进 16px 体现层级
- 滚动条：沿用已落地的 6px 细滚动条（矮屏极端情况下兜底）

## 四、预期效果

- 默认状态下侧栏 7 项，滚动条消失
- 层级清晰：骨架（组）→ 内容（工具），与首页分工明确
- 工具再多（如扩到 30 款）侧栏依然稳定，无需改结构

## 五、备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 分组折叠（推荐） | 滚动消除、层级清晰、与首页同源 | 长尾工具多一次展开点击 | ✅ 采纳 |
| B. 仅高频 + 首页兜底 | 极简 | 需要额外"最近使用"逻辑，长尾工具难找 | 不采纳 |
| C. 窄图标 rail（VS Code 式） | 现代 | 17 个图标仍需滚动，语义弱于文字 | 不采纳 |
| D. 全量平铺 + 细滚动条 | 改动最小 | 未解决重复与滚动根因 | 不采纳 |

## 六、实施范围

- `home_shell.dart`：`_Sidebar` 重构为分组折叠模型，`_HomeShellState` 增加分组展开状态（记忆）
- `home_page.dart`：导出分组定义供侧栏复用（`ToolGroup` 提升为公共类）
- 涉及文件少、无新增依赖，单轮可完成
